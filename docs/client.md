# Client & hooks

`@flefebvre/next-pipe/client` is the consumer side of the [generated route builders](codegen.md) and of form actions: a tiny transport (`callRoute`), the builder factory the generated code uses (`defineRoute`), a pending-state hook (`useApiCall`), a form hook (`useFormAction`), and typed readers for action results (`getActionError`, `getActionInput`).

## The `routes` barrel

Generated by `next-pipe gen` — static segments are properties, dynamic segments are calls, verbs are zero-arg builders:

```ts
import { routes } from "@/generated/routes";

routes.api.notes(id).like.POST();
// → { url: `/api/notes/${id}/like`, method: "POST" }
//   plus phantom types: body, response union, query — read off the route handler
```

The returned object is a `RouteDefinition`: at runtime just `{ url, method }`; at the type level it carries the route's body, response, and query types, extracted from the handler via `import type` (no server code in the bundle).

## callRoute

```ts
import { callRoute } from "@flefebvre/next-pipe/client";

const res = await callRoute(routes.api.notes(id).like.POST(), { json: { like: true } });
// res: { status: 200; json: { liked: boolean } }
//    | { status: 401; json: { error: string } }
//    | { status: 400; json: ... }

if (res.status === 200) {
  res.json.liked; // boolean — narrowed by status
}
```

Semantics worth knowing:

- **Options are required exactly when declared.** A route with a [`BodyValidationMiddleware`](built-in-middlewares.md#bodyvalidationmiddleware) makes `json` mandatory (and typed); one with [`QuerystringMiddleware`](built-in-middlewares.md#querystringmiddleware) makes `query` mandatory. A route with neither takes no options at all.
- **The return type is the route's exact response union** — handler returns *and* middleware interrupts. `fetch` doesn't throw on HTTP error statuses, so a declared `401` comes back as a value you narrow on, not an exception.
- **Anything outside the union throws**: network failures, or a response body that isn't valid JSON.
- **The response is trusted, not re-validated.** The types come from your own handlers; if you need runtime validation of responses, do it at the call site.
- Query serialization: keys with `undefined` values are dropped; everything else goes through `String(...)` into the querystring.

`callRoute` works anywhere `fetch` does — client components, server components, tests.

## useApiCall

A `"use client"` hook wrapping any generated builder with `useTransition` pending state:

```tsx
"use client";

import { useApiCall } from "@flefebvre/next-pipe/client";
import { routes } from "@/generated/routes";

const [toggleLike, isLiking] = useApiCall(() => routes.api.notes(props.id).like.POST(), {
  onSuccess: (res) => {
    switch (res.status) {
      case 200: setLiked(res.json.liked); break;
      case 400: setError("Invalid request"); break;
      default:  setError(res.json.error); // 401 | 404
    }
  },
});

<button onClick={() => toggleLike({ json: { like: !liked } })} disabled={isLiking} />
```

- The dispatch function's argument mirrors `callRoute`'s rules: `params` / `json` / `query` keys exist exactly when the builder and route declare them — `dispatch()` takes no argument at all when nothing is required.
- You can pass the builder directly (`useApiCall(routes.health.GET)`) or close over params as above.
- `onSuccess` receives the full typed response union.
- There is no `onError` yet: if `callRoute` throws (network failure, bad shape), the error propagates.

## getActionError

The typed error reader for [action](action-pipe.md) and [form action](form-action-pipe.md) results. Given a result union and an error key, it returns that key's `data` — precisely typed — or `null`:

```tsx
import { getActionError } from "@flefebvre/next-pipe/client";

const [result, dispatch, isPending] = useActionState(login, null);

const fieldErrors = getActionError(result, "schema");        // { formErrors, fieldErrors } | null
const credentials = getActionError(result, "credentials");   // string | null
```

It accepts `null` (the `useActionState` initial state) and returns `null` for successes and non-matching keys, so chaining reads cleanly:

```ts
setError(getActionError(res, "forbidden") ?? getActionError(res, "notFound") ?? "Error");
```

## getActionInput

The typed reader for the `input` field that [`FormValidationMiddleware` echoes](form-action-pipe.md#how-input-echoing-works) onto form-action results. It returns the echoed values (the raw submitted strings, typed by the schema's keys) or `null` when the result carries none (the `useActionState` initial `null`, or a branch produced [upstream of the validation middleware](form-action-pipe.md#middlewares-on-form-actions)):

```tsx
import { getActionInput } from "@flefebvre/next-pipe/client";

const [result, dispatch, isPending] = useActionState(createNote, null);
const input = getActionInput(result); // { content?: string } | null

<input name="content" defaultValue={input?.content} />;
```

Only error results carry the echo by default, so `result?.input` does not typecheck on the full union; `getActionInput` reads it from any union. [`useFormAction`](#useformaction) returns it as `input`.

## useFormAction

A `"use client"` hook wrapping `useActionState` for a [form action](form-action-pipe.md), made to behave when Next keeps the page alive in a hidden `<Activity>` ([Activity](activity.md)):

```tsx
"use client";

import { useFormAction } from "@flefebvre/next-pipe/client";
import { createNote } from "../actions";

export function NoteForm() {
  const { formKey, formProps, input, error, isPending, result } = useFormAction(createNote, {
    onSuccess: (result) => toast(`Note ${result.data.id} saved`),
    onLeave: "reset",
  });

  return (
    <form key={formKey} {...formProps}>
      <input name="title" defaultValue={input?.title} />
      {error?.type === "titleTaken" && <p role="alert">{error.data}</p>}
      <button disabled={isPending}>Save</button>
      {result?.status === "success" && <p role="status">Saved</p>}
    </form>
  );
}
```

| Returned    | What it is                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------- |
| `formProps` | `{ action, onReset }`, spread onto the `<form>`                                                    |
| `formKey`   | the form's `key`; `onLeave: "reset"` remounts the form through it                                  |
| `input`     | the echoed input of an error result, for `defaultValue`; `null` otherwise                           |
| `error`     | the error branch `{ type, data }`, narrowed by `error?.type`; `null` otherwise                      |
| `isPending` | `true` while the action runs                                                                       |
| `result`    | the latest result, `null` before the first one and once `onLeave` dropped it                        |

- **Fields after a submit**: after an error, every field keeps what the user typed, `<select>` included: `onReset` cancels React's automatic form reset (React ≥ 19.3). A success resets the form.
- **`onSuccess` / `onError`** run once per result, from the dispatch wrapper. Never run a side effect from an effect on `result`: it runs again every time the page is shown.
- **`onLeave`** (`"keep"` by default, `"clearResult"`, `"reset"`) runs when the page is hidden: see [Leaving the page](form-action-pipe.md#leaving-the-page).
- A `redirect(...)` in the action produces no result, so no callback runs; Next remounts the form.

## defineRoute

The factory the [generated modules](codegen.md#what-gets-generated) are built from — you normally never call it yourself:

```ts
export const POST = defineRoute<typeof _POST, { id: string }>(({ id }) => `/api/notes/${id}/like`, "POST");
```

Given a route handler's *type* and a URL template, it returns a builder producing `RouteDefinition`s. The body/response/query types are read off the handler's [config channel](core-concepts.md#the-config-channel) — purely at the type level. If you need a builder for a route outside the generated set (an external API you also control, say), `defineRoute` is exported for that.
